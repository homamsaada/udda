## 🏛️ قرارات أساسية

### بنك أسئلة ضخم (~200K سطر JSON)
- **القرار:** تخزين كل الأسئلة كـ JSON ثابت (لا توليد عند الطلب)
- **السبب:** الجودة المضمونة + الموثوقية + لا تكلفة AI runtime + خصوصية
- **القيد:** ~9.2 MB إجمالي البيانات. يُحمَّل ما يحتاجه المستخدم فقط.

### Lazy loading للتخصصات
- **القرار:** عند فتح الصفحة، يُحمَّل `questions-index.json` فقط (~24 KB). التخصصات تُحمَّل عند الاختيار.
- **السبب:** تجربة سريعة للمستخدم. لو حمّلنا كل شيء (~9 MB) يبطأ التحميل الأولي.
- **التطبيق:** `loadJSON(filename)` يُحمَّل عند الحاجة.

### 6 أنواع أسئلة
- **القرار:** mcq, true_false, fill_blank, matching, sorting, self_assessment
- **السبب:** التنوّع يكسر الرتابة + يقيس مهارات مختلفة
- **التحدي:** كل نوع له schema مختلف، يحتاج معالجة مخصّصة

### الأسئلة الذاتية لا تدخل بالنقاط
- **القرار:** التقييم الذاتي → معامل ضرب فقط (0.7 - 1.3)، لا نقاط مباشرة
- **السبب:** نقيس "السلوك الفعلي" لا "ما يدّعيه المستخدم"
- **النتيجة:** شخص ذو معرفة 80% × مرونة 0.8 = 64 (واعٍ متردّد). شخص 50% × 1.3 = 65 (مبتدئ قابل للتطور). الأخير "أفضل" استراتيجياً.

### الترجيح: جوهرية vs ثقافية
- **القرار:** الجوهرية = 3-4 نقاط، الثقافية = 1 نقطة فقط
- **السبب:** "كم عدد مستخدمي ChatGPT؟" أقل أهمية من "كيف تكتب prompt جيداً؟"

### Canvas Share Image: ألوان داكنة ثابتة (2026-05-10)
- **القرار:** Canvas الـ Share Image يستخدم `.ai-readiness --canvas-*` namespace في CSS، يُقرأ عند الـ render عبر `getCanvasColors()` helper. القيم بقيت داكنة بقصد — الـ Canvas لا يستجيب للثيم.
- **السبب:** صورة المشاركة الاجتماعية يجب أن تبدو متطابقة بين Light/Dark theme لتناسق العلامة البصرية. لو تتبع الثيم، فالـ infographic المُصدَّر يختلف بصرياً بين زائرَين بنفس النتيجة.
- **التمييز عن `--level-*`:** على الصفحة، `--level-aware` = `--warning` (أصفر/كهرماني، semantic). على الـ Canvas، `--canvas-level-aware` = `#3b82f6` (أزرق، perceptual hierarchy). الباليتتان مختلفتان عمداً.
- **خارج النطاق:** تدرّجات CSS في `.air-report-summary.level-aware` (سطور 1019, 1026) و SVG timer ring (`lerpColor` سطور 2441-2443) — مهام أخرى مستقلة عن Canvas.

### مبادئ صياغة الأسئلة (قاعدة ذهبية)
- **التقييم الذاتي غير مباشر دائماً** — لا نسأل "هل أنت مرن؟" بل نضعه في موقف
- **كل الخيارات تبدو عقلانية** — لا "يفضح نفسه"
- **مبدأ التشويق:** السؤال يفاجئ، يثير تفكيراً، أو يتحدى — وإلا يُحذف

## 🏗️ قرارات معمارية

### State machine للمراحل
- مراحل: 0 (welcome) → 1 (general) → 1.5 (specialty) → 2 (specialty + remaining) → results
- **`currentPhase`** يدير الانتقالات
- **`beforeunload`** يمنع الخروج العفوي

### توزيع الأسئلة: 35% عام + 65% تخصصي
- **القرار:** عند اختيار المدة، نقسّم العدد الكلي
- **السبب:** التخصصي يخدم المستخدم أكثر، العام يضع أساساً مشتركاً

### عند تعدد التخصصات: توزيع متساوٍ
- مثال: 16 سؤالاً تخصصياً + 3 تخصصات → 6+5+5

## ⚠️ حالات حافّة معروفة

| الحالة | المعالجة |
|---|---|
| فشل تحميل ملف تخصص | إظهار رسالة + إكمال الاختبار بما توفّر |
| Refresh أثناء الاختبار | تحذير `beforeunload`، إن أصرّ → ينتهي بالنتائج الجزئية |
| المستخدم لا يختار تخصصاً | زر "تخطي" → حساب على العامة فقط |
| انتهاء وقت سؤال | إشارة بصرية + منع الإجابة، يضغط "التالي" يدوياً |

- **مقارنة جماعية حية** — يحتاج backend

## 🎓 دروس مستفادة

- **JSON ضخم يعمل بسرعة** عبر lazy loading — أكثر فعالية من قاعدة بيانات
- **تخصصات بعدد 100 سؤال لكل** كافٍ للعشوائية + التنوّع. الذهاب لـ 200 يضاعف الحجم بدون قيمة كبيرة.
- **مبدأ "السؤال الذي لا يُفاجئ يُحذف"** رفع جودة البنك بشكل ملحوظ.
- **التوقيت الفردي 30-45 ثانية** يمنع البحث الخارجي (40-60 ثا حد أدنى لفتح ChatGPT والسؤال).
