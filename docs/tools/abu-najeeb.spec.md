# 🧮 أبو نجيب | Abu Najeeb — Smart Bill Splitter Spec

> أداة لتقسيم الفواتير والمصاريف بين الأشخاص بأربع طرق، مع خوارزمية ذكية تُقلِّل عدد التحويلات.
>
> **ID:** `abu-najeeb` · **التصنيف:** `everyday` · **الأيقونة:** 🧮

---

## 1. نظرة عامة

### الجمهور
- مجموعات الأصدقاء بعد عزومة أو رحلة
- شركاء سكن يقسّمون الإيجار/الفواتير
- زملاء عمل في غداء جماعي
- عائلات مع مرافقين (أطفال، ضيوف)

### المشكلة
- بعد رحلة جماعية، 4-6 أشخاص دفعوا مبالغ مختلفة لأشياء مختلفة → حساب يدوي مرهق
- "كل واحد يطلع نصيبه" يُنتج عدداً كبيراً من التحويلات (N×M)
- المرافقون (طفل، زوجة، ضيف) يحتاجون منطقاً مختلفاً
- لا أداة عربية تخدم هذا بشكل واضح

### النتيجة
- أربع طرق تقسيم تغطّي 95% من الحالات اليومية
- خوارزمية Greedy تُنتج **أقل عدد ممكن** من التحويلات
- دعم المرافقين بثلاثة أنصبة (كامل/نصف/ربع)
- نتائج قابلة للنسخ والتصدير كصورة للمشاركة

## 2. التبويبات الأربعة

### 2.1 التقسيم المتساوي (Equal Split)

**الفكرة:** الكل يدفع بالتساوي بناءً على المبلغ + الضريبة + الإكرامية.

**المُدخلات:**
- المبلغ الإجمالي
- الضريبة (%)
- الإكرامية (%)
- قائمة الأشخاص (مع المرافقين)

**المعادلة:**
```
المبلغ النهائي = الإجمالي × (1 + ضريبة% + إكرامية%)
مجموع الأنصبة = Σ weight(p) = Σ (1 + companions × shareMultiplier)
نصيب الشخص = round(المبلغ النهائي × weight(p) / مجموع الأنصبة)
```

### 2.2 حسب الاستهلاك (By Consumption)

**الفكرة:** كل شخص يدفع ثمن ما طلبه + نصيبه من المشترك (مقبلات/مشروبات).

**المُدخلات:**
- قائمة الطلبات: لكل طلب {اسم، سعر، لمن؟ (شخص واحد / الجميع / محددون)}
- الضريبة (%)
- الإكرامية (%)

**المنطق:**
- طلب لشخص واحد → كامل سعره عليه
- طلب مشترك → يقسَّم على الأشخاص المحدَّدين (مع weights)
- ضريبة + إكرامية تُضاف نسبياً على نصيب كل شخص

### 2.3 من دفع لمن (Settlement) ⭐

**الفكرة:** بعد رحلة، أشخاص مختلفون دفعوا لأشياء مختلفة. الأداة تحسب التسوية الدُّنيا.

**المُدخلات:**
- قائمة المصاريف: لكل مصروف {وصف، مبلغ، من دفع؟، لمن؟ (الجميع / محددون)}

**خوارزمية Greedy Settlement:**

```
1. لكل شخص:
   net[p] = Σ(ما دفعه) - Σ(نصيبه من كل مصروف)

2. قسِّم:
   creditors = sort desc (net > 0)
   debtors   = sort asc  (net < 0)

3. while creditors && debtors:
     c = creditors[0]; d = debtors[0]
     amount = min(c.net, |d.net|)
     transfers.push({from: d, to: c, amount})
     c.net -= amount; d.net += amount
     remove zeros
```

**النتيجة:** قائمة "X يحوّل لـ Y مبلغ Z" بأقل عدد من التحويلات.

### 2.4 بالنسب (By Percentage)

**الفكرة:** كل شخص له نسبة محدّدة من المبلغ (شركاء بنسب، إيجار بغرف مختلفة).

**المُدخلات:**
- المبلغ الإجمالي
- قائمة الأشخاص بنِسب (% أو وحدات)
- الضريبة + الإكرامية اختياري

**التحقق:**
- وضع `%`: المجموع يجب = 100% (إنذار إن لم يكن)
- وضع `units`: تحوَّل تلقائياً لنسب مئوية

## 3. مفهوم المرافقين (Companions)

كل شخص له:
- `companions`: عدد المرافقين (افتراضي 0)
- `companionShare`: نوع نصيب كل مرافق

**الأنصبة الثلاثة (presets):**
| النصيب | المضاعف | مثال |
|---|---|---|
| كامل (`full`) | 1.0 | زوج/ضيف بالغ |
| نصف (`half`) | 0.5 | طفل عمر 8 سنوات |
| ربع (`quarter`) | 0.25 | طفل صغير جداً |

**المعادلة:** `weight(p) = 1 + companions × multiplier`

**مثال:** أحمد + زوجته + طفل (نصف) → companions=2، companionShare=`half` لو الطفل، أو نضع زوجته كشخص منفصل ونترك أحمد مع طفل واحد بنصف. **القرار:** UI بسيط يفترض كل المرافقين بنفس النصيب (Cmd: full/half/quarter).

**خارج النطاق (v2):** مرافقون بأنصبة مخصّصة (custom %).

## 4. القواعد العامة

| القاعدة | التفاصيل |
|---|---|
| الأرقام | أرقام صحيحة فقط (`Math.round` بعد كل قسمة) |
| العملة | حقل اختياري نصّي، يُلصق بالنتيجة، لا يدخل الحساب |
| الحدّ الأدنى | 2 أشخاص |
| الحدّ الأقصى | 50 شخصاً (UI hard limit) |
| الطلبات/مصاريف | لا حدّ صلب، ينصح ≤ 100 |
| التوازن | آخر شخص دائن يحصل على `total - Σ(الآخرين)` لمعالجة الـ rounding |

## 5. الميزات الإضافية

### 5.1 جرّب مثالاً (`seedDemo`)

زر لكل تبويب يملأ المُدخلات بسيناريو واقعي:
- **متساوٍ:** 4 أشخاص، 1000، 15% ضريبة، 10% إكرامية، طفل واحد بنصف
- **استهلاك:** ستيك/سلطة/بيتزا + مقبلات/مشروبات مشتركة
- **من دفع لمن:** 4 أشخاص، 3 مصاريف (بنزين/فندق/أكل) → 3 تحويلات
- **بالنسب:** 3000 إيجار، 50/30/20

### 5.2 نسخ النتيجة كنص (`copyResult`)

Clipboard API يُنسّق النتيجة كنص مقروء:
```
💰 ملخص الرحلة
المجموع: 1400 ر.س
عدد الأشخاص: 4
نصيب الفرد: 350 ر.س

📋 التسوية (3 تحويلات):
- عمر ← خالد: 350
- سارة ← خالد: 100
- سارة ← أحمد: 50

✅ وفّر أبو نجيب 3 تحويلات
```

### 5.3 sessionStorage (Auto-save)

حفظ تلقائي شفّاف. عند `F5` تعود الحالة كاملة (الأشخاص + بيانات كل التبويبات). مفتاح: `udda:abu-najeeb:session`.

### 5.4 localStorage (Saved Groups)

مفتاح: `udda:abu-najeeb:groups`. UI لإدارة المجموعات المحفوظة:
- زر "حفظ هذه المجموعة" → يطلب اسماً (مثلاً "شلة الجامعة")
- قائمة منسدلة بالمجموعات المحفوظة → استرجاع
- زر حذف لكل مجموعة

نحفظ **الأشخاص فقط** (مع المرافقين)، لا بيانات التبويبات الحالية.

### 5.5 تصدير كصورة (html2canvas)

- المكتبة محلية في `src/assets/vendor/html2canvas.min.js`
- تحميل lazy: السكربت لا يُحمَّل إلا عند الضغط الأول على زر "تصدير صورة"
- يلتقط `.calc-result` ويُنزّل PNG باسم `abu-najeeb-<tab>-<timestamp>.png`

## 6. الحالات الحافّة

| الحالة | السلوك |
|---|---|
| أقل من شخصين | رسالة "أحتاج شخصين على الأقل" |
| مبلغ ≤ 0 | رفض + رسالة "أدخل مبلغاً صحيحاً" |
| نسب ≠ 100% (Tab 4) | إنذار بصري + ملخّص الفرق |
| كل المصاريف على شخص واحد (Tab 3) | الباقون يدفعون له بالتساوي |
| الكل دفع نصيبه بالضبط (Tab 3) | "الجميع متعادل، لا توجد تحويلات 🎉" |
| حذف شخص له مصاريف/طلبات | حوار تأكيد + cascade إزالة من `sharedWith`/`paidBy` (مع تنبيه لو الشخص هو `paidBy` مصروف ما → منع الحذف) |
| `Σ(rounding errors)` (Tab 3) | آخر دائن يحصل على الفرق لإغلاق التوازن |

## 7. الملاحظات المعمارية

### الملف
```
src/tools/abu-najeeb.html (~متوقع 800-1000 سطر)
```

### Wrapper class
`.abu-najeeb`

### Prefix للأنماط الخاصة
`an-*` (an = abu najeeb)

### استهلاك Standard Calc Kit
```
.calc-tabs, .calc-tab, .calc-pane         ← التبويبات
.calc-form, .calc-form-row, .calc-form-group  ← حقول الإدخال
.calc-stats-grid, .calc-stat-card         ← عرض نتائج كل شخص
.calc-result.show                         ← حاوية نتائج fade-in
```

### Reactivity
- نمط محلي: `state` object + `render()` تُستدعى عند كل تغيير
- عدة `render*` متخصصة لتجنّب re-render كامل غير ضروري:
  - `renderPeopleBar()` عند تغيّر الأشخاص فقط
  - `renderActiveTab()` عند تبديل التبويب أو تعديل بياناته
  - `renderResult()` عند الحاجة لعرض الناتج

### Persistence
- `sessionStorage["udda:abu-najeeb:session"]` — كامل الـ state، auto-save
- `localStorage["udda:abu-najeeb:groups"]` — مصفوفة المجموعات المسمّاة
