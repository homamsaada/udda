# 🧮 أبو نجيب | Abu Najeeb — Trip Settlement Calculator Spec

> أداة لتسوية مصاريف الرحلات الجماعية بنموذج **أمين الصندوق** + **buckets للحصص**: عدد كلّي للمشاركين موزَّع على نصاب كامل/نصف/ربع، ومن اشترى شيئاً يُضاف بالاسم. كل شخص يدفع حصته مباشرة للأمين، فلا فوضى تحويلات في المجموعات الكبيرة.
>
> **ID:** `abu-najeeb` · **التصنيف:** `everyday` · **الأيقونة:** 🧮

---

## 1. نظرة عامة

### الجمهور
- مجموعات الرحلات الكبيرة (10+ أشخاص شائع، حتى 50)
- شركاء سكن لمصاريف مشتركة
- مجموعات صغيرة (4-6) في عشاء/سفر قصير

### المشكلة
- بعد رحلة جماعية، عدّة أشخاص دفعوا لأشياء مختلفة من مال خاص
- في الرحلات الكبيرة (20+ شخص)، إدخال كل شخص باسمه غير عملي
- "كل شخص يطلع نصيبه" يُنتج فوضى تحويلات (N×M)
- خوارزميات Greedy تُقلِّل العدد، لكن كل شخص قد يتعامل مع عدّة أشخاص = مرهق نفسياً
- **نموذج "أمين الصندوق"** (أمير الرحلة): شخص واحد يجمع من الجميع ويُسلّم للجميع → كل فرد له معاملة واحدة فقط

### النتيجة
- **عرض مزدوج حصرياً:**
  - **View A (inbound):** ما يُسلَّم للأمين — تجميع للـ anonymous bulk + سطر فردي لكل buyer مدين
  - **View B (outbound):** ما يردّه الأمين للـ buyers الذين دفعوا زيادة

## 2. الفلسفة المعمارية

### الإصدار الأول (محذوف)
4 تبويبات (متساوي/استهلاك/تسوية/نسب). خَلَطت بين طُرق التقسيم والمخرَج النهائي.

### v1 (refactor 2026-05-11 — محذوف جزئياً)
Trip-only موحَّد بنموذج Treasurer + بديل Greedy. لكن النموذج كان يفترض إدخال كل شخص بالاسم، مع مفهوم "مرافقون" لكل شخص.

### v2 (refactor 2026-05-12 — الحالي)
**نموذج Bulk + Buyers، مع إلغاء مفهوم المرافقين كلّياً:**

- المُدخَل = **العدد الكلي للمشاركين** + توزيع على **4 buckets** (full anonymous / half anonymous / quarter anonymous / named buyers)
- كل شخص في الرحلة يُعَدّ في **bucket واحد فقط**
- الـ buyers مسمَّون لأنهم اشتروا شيئاً ولهم expenses
- الـ anonymous مجرَّد عدد (لا أسماء، لا تتبّع فردي)
- المخرَج = تسوية بأمين الصندوق فقط (لا Greedy)

**النطاق:** الأداة لرحلات يدفع فيها كل مشارك حصته **مباشرة** لأمين الصندوق. ليست لحالات "أب يدفع عن عائلته" (لو احتاج المستخدم تتبّع ذلك، يضيفه كـ buyer واحد بمضاعف نصابه المُجمَّع).

## 3. التدفّق

```
1. (اختياري) عملة نصّية تُلصق بالنتيجة
2. إدخال العدد الكلي للمشاركين (1-50)
3. (افتراضي) كل المشاركين بنصاب كامل → تعديل half/quarter لمن يدفع نصف/ربع
4. إضافة الـ buyers بالاسم (لكل واحد share factor: full/half/quarter)
   ← كل buyer يُحسَب من ضمن العدد الكلي، وينقص bulk.full تلقائياً
5. تسجيل المصاريف (وصف + مبلغ + paidBy ← من buyers)
6. (تلقائي) اختيار أمين الصندوق = أكبر دائن. يمكن تغييره من dropdown.
7. عرض النتيجة في وجهَين:
   - View A: ما يُسلَّم للأمين (bulk lines + debtor buyer lines)
   - View B: ما يردّه الأمين (creditor buyer lines)
```

## 4. نموذج أمين الصندوق

### الفكرة
**كل مشارك يتعامل مع شخص واحد (الأمين):**
- المشاركون الـ anonymous: يُسلّمون حصصهم للأمين (مجمَّع حسب الـ factor)
- الـ buyers الذين دفعوا أقل من حصتهم (debtors): يُسلِّمون الفرق للأمين
- الـ buyers الذين دفعوا أكثر من حصتهم (creditors): يأخذون الفرق من الأمين
- الأمين: يجمع كل العجز ويُسلّم كل الفائض، الباقي صافيه هو

### اختيار الأمين

**تلقائي (افتراضي):**
- أكبر دائن (buyer ذو أكبر `net` موجب)
- الفكرة: غالباً هو الذي تكفّل بأكبر النفقات، فمن المنطقي أن يُكمل دور التجميع

**يدوي:**
- المستخدم يُغيِّر من dropdown
- مفيد لو شخص آخر متطوّع لإدارة الصندوق (مدير الرحلة، الأكبر سناً، إلخ)

**قيد:** الأمين يجب أن يكون buyer (مسمَّى). لا يمكن لأحد anonymous أن يكون أميناً.

### مثال

12 مشارك، 8 anonymous بنصاب كامل + 4 buyers (أحمد، خالد، سارة، عمر — كلهم بنصاب كامل).
المصاريف: بنزين 480 (أحمد)، فندق 1800 (خالد)، عشاء 350 (سارة)، تذاكر متحف 60 (عمر).
مجموع = 2690 ÷ 12 = **224/full share**.

```
⭐ أمين الصندوق: خالد (مقترح تلقائياً — أكبر دائن)

💰 يُسلَّم لخالد (View A):
  - 8 شخص بنصاب كامل × 224 = 1,792
  - عمر (كامل): 166      ← دفع 60، حصته 224، عليه فرق

💸 خالد يردّ (View B):
  - أحمد: 256      ← دفع 480، حصته 224، له فرق
  - سارة: 126      ← دفعت 350، حصتها 224، لها فرق

(صافي خالد = 1576 من جمعه 1958 وسداده 382 = 1576 ✓)
```

## 5. Bulk Shares — 3 buckets فقط

**الانتظام الذهبي:**

| Bucket | المعنى | الـ multiplier |
|---|---|---|
| `bulk.full` | عدد anonymous بنصاب كامل | 1.0 |
| `bulk.half` | عدد anonymous بنصف نصاب | 0.5 |
| `bulk.quarter` | عدد anonymous بربع نصاب | 0.25 |
| `buyers[]` | الأفراد المسمَّون، كل واحد له `shareFactor` (full/half/quarter) | حسب الـ factor |

**Invariant:** `bulk.full + bulk.half + bulk.quarter + buyers.length === total`

**قواعد التعديل:**
- عند زيادة `total` (مثلاً من 10 إلى 12): يُضاف الفرق إلى `bulk.full`
- عند نقصان `total`: يُنقَص من `bulk.full` أولاً، ثم `bulk.half`، ثم `bulk.quarter`. لا يمكن أن يصل `total < buyers.length` (clamp)
- عند زيادة `bulk.half` أو `bulk.quarter` بمقدار X: يُنقَص `bulk.full -= X` (cascade)
- عند إضافة buyer: ينقص `bulk.full -= 1` (لو ≥1)، وإلا `total += 1`
- عند حذف buyer: يزيد `bulk.full += 1` (يعود إلى bulk)

**خارج النطاق (v2.1):** نسب مخصّصة (custom %).

## 6. القواعد العامة

| القاعدة | التفاصيل |
|---|---|
| الأرقام | صحيحة فقط، `Math.round` بعد كل قسمة |
| العملة | حقل اختياري نصّي، يُلصق بالنتيجة، لا يدخل الحساب |
| التنسيق الموقعي | **الأرقام بالإنكليزية في AR + EN** (قرار 2026-05-11) |
| الحدّ الأدنى | total ≥ 1 + buyer واحد + مصروف واحد |
| الحدّ الأقصى | total = 50 مشاركاً |
| التوازن | rounding diff يُمتَصّ في آخر سطر، بحيث يبقى صافي الأمين = sum(inbound) - sum(outbound) |
| الأمين الافتراضي | أكبر دائن (تلقائي)، إن لا أحد له صافٍ موجب → أول buyer |

## 7. الميزات

### 7.1 جرّب مثالاً (`seedDemo`)
رحلة عملية: 12 مشارك، 4 buyers (أحمد، خالد، سارة، عمر) كلهم بنصاب كامل، و 8 anonymous بنصاب كامل، 4 مصاريف.
مُصمَّمة لتختبر **حالة مختلطة** (3 creditors + 1 debtor): خالد كأمين، عمر مدين، الباقي دائنون.

### 7.2 نسخ النتيجة (`copyResult`)
نصّ منسَّق لكلا الوجهين:
```
💰 أبو نجيب — تسوية الرحلة
مجموع المصاريف: 2690 ر.س
عدد المشاركين: 12
تكلفة النصاب الكامل: 224 ر.س

⭐ أمين الصندوق: خالد (مقترح تلقائياً)

💰 يُسلَّم لـ خالد:
- 8 شخص بنصاب كامل × 224 ر.س = 1792 ر.س
- عمر (كامل): 166 ر.س

💸 خالد يردّ:
- أحمد: 256 ر.س
- سارة: 126 ر.س
```

### 7.3 sessionStorage + Saved Groups
- `udda:abu-najeeb:session` — auto-save الحالة الكاملة (schema=`v2`)
- `udda:abu-najeeb:groups` — مجموعات أشخاص محفوظة بالاسم
  - **يحفظ buyers فقط** (اسم + shareFactor)
  - **لا يحفظ trip config** (total + bulk + expenses) — كل رحلة مختلفة
  - عند التحميل: يُستبدَل `state.buyers` بالمحفوظ، ويُعاد ضبط `total = buyers.length` و `bulk = {0,0,0}`، يبدأ المستخدم رحلة جديدة

### 7.4 تصدير صورة (html2canvas vendor lazy)
- ~195KB، يُحمَّل عند الطلب فقط
- يلتقط `.calc-result` كاملة (stats + view A + view B)

## 8. الحالات الحافّة

| الحالة | السلوك |
|---|---|
| `total = 0` | رسالة "أدخل العدد الكلي للمشاركين أولاً" + إخفاء الكل ما عدا trip-config |
| `total > 0` ولا buyers | رسالة "أضف شخصاً واحداً مسمَّى على الأقل لتسجيل المصاريف" + إخفاء expenses + result |
| محاولة جعل `total < buyers.length` | clamp عند `buyers.length` |
| محاولة جعل `bulk.half/quarter` > المتاح في `bulk.full` | clamp عند الحدّ الأقصى المتاح |
| لا مصاريف بعد | لا نتيجة (`.calc-result` مخفي) |
| مبلغ ≤ 0 أو غير رقمي | رفض + رسالة |
| الكل متعادل | "✅ الجميع متعادل، لا توجد ديون 🎉" في View A |
| الأمين فقط creditor، الباقون متعادلون | View A فارغ (banner) أو يحتوي bulk فقط، View B فارغ |
| حذف buyer = `paidBy` لمصروف | منع الحذف + رسالة "غيِّر الدافع أولاً" |
| حذف buyer = الأمين | revert to auto |
| Σ rounding errors ≠ 0 | امتصاص في آخر سطر |

## 9. الملاحظات المعمارية

### الملف
```
src/tools/abu-najeeb.html (~1,500 سطر)
```

### Wrapper class
`.abu-najeeb`

### Prefix للأنماط الخاصة
`an-*`

### استهلاك Standard Calc Kit
```
.calc-form-group               ← مجموعات حقول الإدخال
.calc-stats-grid               ← stats panel (Total + CPS + People + Breakdown)
.calc-stat-card[.highlight]    ← بطاقات stats الفردية
.calc-result.show              ← حاوية النتيجة
```

⚠️ **لا تبويبات، لا Greedy، لا share pills للمصاريف.**

### State (مركزي)
```js
state = {
  currency: '',
  total: 0,
  bulk: { full: 0, half: 0, quarter: 0 },
  buyers: [{ id, name, shareFactor: 'full'|'half'|'quarter' }],
  expenses: [{ id, description, amount, paidBy: buyerId }],
  treasurer: buyerId | null,       // null = auto = biggest creditor
  editingBuyerId: null,
  editBuffer: null
};
// Invariant: bulk.full + bulk.half + bulk.quarter + buyers.length === total
```

### Persistence
- `sessionStorage["udda:abu-najeeb:session"]` (schema=`v2`)
- `localStorage["udda:abu-najeeb:groups"]` (buyers فقط)

### Reactivity
كل تعديل state يستدعي `renderAll()` → `renderTripConfig + renderBuyersList + renderExpenses + renderResult + saveSession`.
