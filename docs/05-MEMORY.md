# 🧠 ذاكرة المشروع | Site Memory

> القرارات الكبرى التي شكّلت عُدّة، ومراجعها، والدروس المستفادة عبر الأدوات.
>
> هذا الملف يكمّل [`02-PRINCIPLES.md`](02-PRINCIPLES.md) — المبادئ تقول **"ماذا"**، الذاكرة تقول **"لماذا"** + **"ماذا تعلّمنا"** + **"متى قد يتغيّر القرار"**.

---

## 🌟 الفلسفة العامة

> **عُدّة "static-first"، وليست "static-only".**
>
> الأساس ساكن (HTML/CSS/JS بدون backend). معظم الأدوات الحالية والقادمة كذلك. لكن **أداة محددة** قد تنمو لتحتاج backend (تسجيل، مزامنة، API خارجي) — في هذه الحالة، نضيف backend **جزئية معزولة لها فقط**، لا نُحوّل الموقع كله.
>
> هذا التمييز مهم: نحن لا نمنع التطوّر، نمنع التعقيد بلا حاجة.

---

## 🔒 الفئة 1: مبادئ فلسفية ثابتة (لا تتغيّر)

هذه قرارات قِيَمية، لن تتغيّر بدون إعادة تعريف عميقة للمشروع.

### الخصوصية أولاً
- **لا تتبّع** للمستخدم (لا Google Analytics، لا Facebook Pixel، لا fingerprinting)
- **لا جمع بيانات شخصية** بلا حاجة جوهرية
- **الحسابات الحساسة client-side** افتراضياً
- **عند الحاجة لخادم لاحقاً** (تسجيل اختياري لأداة محددة): privacy-by-design — أقل بيانات ممكنة، تشفير، لا مشاركة

### ثنائية اللغة من البداية
- العربية والإنجليزية معاً، RTL/LTR كاملان
- ليست "لغة أساسية + ترجمة" — كلتاهما أصيلتان

### مجاني للجميع
- لا paywalls، لا "premium tier" يخفي ميزات أساسية
- الدخل من إعلانات AdSense غير مزعجة فقط
- (تسجيل اختياري لميزات إضافية محتمل، لكن دائماً المحتوى الأساسي مجاني)

### العربية أصيلة
- ليست ترجمة آلية من الإنجليزية
- المصطلحات الفقهية والطبية بدقّة (مع transliteration حين يلزم)

### إخلاء المسؤولية للأدوات الحساسة
- إسلامية: "ليست فتوى"
- مالية بفائدة: تنبيه الربا
- طبية: "استشر طبيباً"

## ⚙️ الفئة 2: خيارات تطبيقية حالية (قابلة للتطوّر تحت شروط)

هذه قرارات **تنفيذية** اخترناها لأنها الأنسب الآن. قد تتغيّر لو الظروف تطلّبت ذلك.

| القرار الحالي | السبب الآن | شرط التغيّر |
|---|---|---|
| **Vanilla JS** بدلاً من React/Vue/Svelte | الموقع بسيط، الـ framework يضيف 100KB+ بلا قيمة | لو state management بات معقّداً عبر أدوات (مزامنة مفضلات، تتبع نتائج، تكاملات) |
| **Static-first** كأساس | خصوصية + سرعة + استضافة مجانية + لا تعقيد | أداة محددة تتطلّب backend → backend جزئية لها فقط |
| **لا CDN في الإنتاج** (إلا Google Fonts حالياً) | تتبّع طرف ثالث | لو وجدنا CDN يحترم الخصوصية بشكل مقبول، أو احتجنا أداء أفضل |
| **لا اختبارات آلية** (Jest، Playwright، إلخ) | البناء + الفحص اليدوي يكفيان حتى الآن | لو bug خطير حدث (خصوصاً في الأدوات الفقهية)، أو الأدوات تعقّدت بشكل يحتاج تحقّقاً صارماً |
| **لا TypeScript** | يحتاج compile step، يُعقّد `build.js` البسيط | لو bugs نوع type تكرّرت، أو state management بات معقّداً |
| **لا Sass/Less** | CSS variables الحديثة تكفي | غير مرجَّح يتغيّر |
| **`build.js` واحد** بدل bundler | بسيط، لا webpack/vite/rollup | لو احتجنا code splitting، tree shaking، أو module bundling حقيقي |
| **`i18n.json` واحد ضخم** | مصدر حقيقة موحَّد، سهل المراجعة | عند 30+ أداة قد نقسّمه لـ `i18n/{tool}.json` |

## 📅 الفئة 3: حالة حالية (قد تُضاف لأدوات محددة لاحقاً)

هذه أشياء **لا نفعلها افتراضياً**، لكن أداة محددة قد تستفيد منها فعلاً.

| لا نفعله افتراضياً | قد نفعله لـ... | مثال محتمل |
|---|---|---|
| **التسجيل/الحسابات** | أداة تحتاج حفظ بيانات المستخدم عبر الأجهزة | حفظ نتائج ai-readiness ومقارنتها عبر الزمن، GPA tracker متعدّد الفصول |
| **قواعد البيانات** | أداة تحتاج تخزين persistent | tracker للزكاة السنوية، شجرة عائلة سحابية، نتائج اختبارات |
| **Backend جزئي** (serverless) | أداة تتكامل مع API خارجي | محوّل عملات بأسعار حية، مولّد QR متقدّم |
| **PWA / Service Workers** | تمكين offline support | يُضاف للموقع كله إن قرّرنا |
| **Native apps (iOS/Android)** | حالياً غير مخطّط — Web App يكفي | لا نمنعه إن أصبح ضرورياً، لكن غير مرجَّح |
| **AI integration runtime** (LLM API calls) | نادر — تكلفة + خصوصية | حالات محدودة جداً، لو أداة معينة تستفيد بشكل واضح |

**القاعدة:** لو نضيف أحد هذه، نضيفه **لأداة محددة معزولة**. الأدوات الأخرى تبقى static.

---

## 🚫 الفئة 4: أشياء لن نفعلها أبداً (قرار قِيَمي)

ليست خياراً تنفيذياً — هذه مخالفة لفلسفة الموقع.

- ❌ **تتبّع المستخدم** بأي شكل (analytics، pixels، fingerprinting)
- ❌ **بيع البيانات** أو مشاركتها مع أطراف ثالثة بدون موافقة صريحة
- ❌ **Paywalls / اشتراكات** تخفي ميزات أساسية
- ❌ **Dark patterns** — خداع المستخدم لاتخاذ قرارات
- ❌ **إعلانات تطفلية** — popups، autoplay video، layout shifts، تتبّع
- ❌ **ترجمة آلية بدون مراجعة** — "فقدان السياق" غير مقبول

## 🎓 دروس مستفادة عبر الأدوات

### من inheritance-calculator
- **التعقيد الفقهي > التعقيد البرمجي.** صرفنا ~60% على فهم الفقه، 40% على الكود.
- **4 مذاهب يحتاج abstraction قوي.** نقطة قرار واحدة (`assignShares()`) تعدّل سلوكها حسب المذهب.
- **حالات الورثة الديناميكية** تحتاج تصميم state من البداية.

### من ai-readiness
- **بنية ملفات JSON ضخمة (200K سطر) تعمل بسرعة عبر lazy loading.**
- **التحميل عند الطلب** أفضل من تحميل كل شيء مسبقاً.
- **مبادئ صياغة الأسئلة** (مواقف، تشويق، تقييم ذاتي غير مباشر) أهم من الكود نفسه.

### من العمل على الموبايل
- **`inheritance-calculator` هي مرجعنا.** كل اختبار موبايل يبدأ منها.
- **`flex-wrap: wrap` للتبويبات إلزامي.** `overflow-x: auto` يكسر اللمس.
- **box-sizing: border-box** غير قابل للتفاوض.

### من الترجمة
- **العربية ليست ترجمة، الإنجليزية ليست ترجمة.** كل لغة تُكتب أصيلة.
- **searchTerms يجب أن تشمل العامي والأخطاء الإملائية.**
- **المصطلحات الفقهية بـ transliteration** ("Kaffarat al-Yamin" أفضل من "Oath Penalty").

### من البناء والنشر
- **`dist/` لا يُتتبع في git.** قرار صحيح — git history أنظف.
- **GitHub Actions auto-merge** يُسرّع التطوير لكنه يحتاج فحصاً قبل push.
