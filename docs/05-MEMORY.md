## 🏛️ قرارات معمارية أساسية

### Static-first بدلاً من SaaS
- **التاريخ:** 2024 (البداية)
- **القرار:** موقع ساكن (HTML/CSS/JS) بدون backend ولا قاعدة بيانات
- **السبب:** خصوصية للمستخدم + سرعة + لا تكاليف خوادم + سهولة النشر + إمكانية offline (عبر PWA لاحقاً)
- **البديل المرفوض:** SaaS — تسجيل، نقل بيانات، تكلفة استضافة، تعقيد

### Vanilla JS بدلاً من Framework
- **القرار:** لا React/Vue/Svelte
- **السبب:** الموقع بسيط (حاسبات + تنقل)، الـ framework يضيف 100KB+ بدون قيمة جوهرية
- **متى يتغيّر هذا القرار:** لو state management بات معقداً عبر أدوات، أو لو نضطر لـ TypeScript

### Build script واحد بدل bundler
- **القرار:** `build.js` يحوي القالب والمنطق inline
- **السبب:** لا webpack/vite/rollup — overhead دون فائدة لموقع ثابت بسيط
- **القيد المعروف:** ملف واحد ضخم (~1,400 سطر) قد يصعب صيانته عند 50+ أداة. سنقسّمه عند الحاجة.

### Single Source of Truth للنصوص (`i18n.json`)
- **القرار:** ملف واحد لكل النصوص العربية والإنجليزية
- **السبب:** سهولة الترجمة + المراجعة + لا قلق "أين توجد الترجمة؟"
- **القيد:** الملف يكبر (~2,000 سطر الآن). نقسّمه عند 30+ أداة على الأرجح.

### CSS variables بدلاً من Sass/Less
- **القرار:** متغيرات CSS الأصلية، لا preprocessor
- **السبب:** Native browser support، يدعم runtime theme switching بسلاسة، صفر build overhead

## 🚫 قرارات "ما لا نفعله" (مع السبب)

| لا نفعل | السبب |
|---|---|
| لا CDN في الإنتاج (Google Fonts استثناء حالي قد نُلغيه) | تتبع طرف ثالث + خصوصية |
| لا Google Analytics / Tag Manager | خصوصية + تجنّب AdBlocker |
| لا تسجيل/حسابات | تعقيد + بيانات حساسة |
| لا اشتراكات مدفوعة | الموقع للجميع |
| لا تطبيق native (iOS/Android) | Web App يكفي ويعمل عبر كل الأجهزة |
| لا اختبارات آلية حالياً | overhead عالٍ — البناء + الفحص اليدوي يكفيان حتى الآن |
| لا TypeScript | Vanilla JS كافٍ، TypeScript يحتاج build pipeline أعقد |

## 🎓 دروس مستفادة عبر الأدوات

### من inheritance-calculator
- **التعقيد الفقهي > التعقيد البرمجي.** صرفنا ~60% من الوقت على فهم الفقه (المذاهب الأربعة + حالات نادرة)، 40% على الكود.
- **4 مذاهب يحتاج abstraction قوي.** النمط المعتمد: نقطة قرار واحدة (`assignShares()`) تعدّل سلوكها حسب المذهب.
- **حالات الورثة الديناميكية** (طبقات أحفاد بلا حد) تحتاج تصميم state من البداية.

### من ai-readiness
- **بنية ملفات JSON ضخمة (200K سطر) تعمل بسرعة عبر lazy loading.**
- **التحميل عند الطلب** (specialty file حين يُختار) أفضل من تحميل كل شيء مسبقاً.
- **مبادئ صياغة الأسئلة** (مواقف، تشويق، تقييم ذاتي غير مباشر) أهم من الكود نفسه.

### من العمل على الموبايل
- **`inheritance-calculator` هي مرجعنا.** كل اختبار موبايل يبدأ منها.
- **`flex-wrap: wrap` للتبويبات إلزامي.** `overflow-x: auto` يكسر اللمس.
- **box-sizing: border-box غير قابل للتفاوض** — أي عنصر يتجاوز عرض الشاشة يكسر zoom.

### من الترجمة
- **العربية ليست ترجمة، الإنجليزية ليست ترجمة.** كل لغة تُكتب أصيلة.
- **searchTerms يجب أن تشمل العامي والأخطاء الإملائية الشائعة** ("بالميه" + "بالمئة" + "نسبه" + "نسبة").
- **المصطلحات الفقهية بـ transliteration** ("Kaffarat al-Yamin" أفضل من "Oath Penalty").

### من البناء والنشر
- **`dist/` لا يُتتبع في git.** كان قراراً صحيحاً — git history أنظف، deploy يبني نسخة طازجة كل مرة.
- **GitHub Actions auto-merge** من `claude/**` إلى `main` يُسرّع التطوير لكنه يحتاج فحص قبل push.

## 📚 مراجع خارجية مرجعية

### للأدوات الإسلامية
- **AAOIFI** — معايير المحاسبة والمراجعة للمؤسسات المالية الإسلامية (المعيار 35 للزكاة)
- **مجمع الفقه الإسلامي الدولي** — قرارات معاصرة (الأسهم، العملات الرقمية، إلخ)
- **المغني** (ابن قدامة) — الفقه الحنبلي المقارن
- **المجموع** (النووي) — الفقه الشافعي
- **بدائع الصنائع** (الكاساني) — الفقه الحنفي
- **شرح الخرشي** — الفقه المالكي

### للأدوات الطبية
- **WHO** — BMI Standards, WHR criteria
- **Mifflin-St Jeor 1990** — BMR formula (Am J Clin Nutr)
- **Devine 1974** — IBW formula (Drug Intell Clin Pharm)
- **Deurenberg 1991** — Body Fat formula (Br J Nutr)

### للـ SEO وWeb Standards
- **Schema.org** — structured data conventions
- **Google Search Central** — hreflang، mobile-first indexing
- **MDN** — RTL/LTR, logical CSS properties
